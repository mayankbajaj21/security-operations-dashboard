# Milestone 2 — ML Preprocessing Documentation

## 1. Purpose & Overview
This document formalizes the ML preprocessing pipeline implemented for Milestone 2 of the AI-Assisted Threat Detection / Security Operations Dashboard project. The preprocessing pipeline transforms enriched security event telemetry (`data/processed/enriched_security_events.csv`) into a clean, normalized, model-ready feature matrix suitable for unsupervised anomaly detection models (such as Isolation Forest).

The preprocessing script is implemented at:
`backend/ml/preprocessing.py`

The fitted preprocessor object is serialized and saved to:
`backend/models/preprocessor.pkl`

The output feature matrix is saved to:
`data/processed/m2_feature_matrix.csv`

---

## 2. Input Dataset Summary
- **Source**: `data/processed/enriched_security_events.csv` (derived from M1 data collection and enrichment pipeline).
- **Record Count**: 1,800 security event records.
- **Traceability**: `event_id` is preserved as the first column in the CSV output to map predictions back to canonical event records.

## 4. Derived Feature Calculations & Operational Assumptions

### A. Operational Business-Hours Assumption (`after_hours_activity`)
- **Assumption**: Standard operational business hours are assumed to be **08:00 AM to 06:00 PM (08:00–18:00)**.
- **Implementation**: The preprocessor exposes configurable parameters `business_hours_start` (default `8`) and `business_hours_end` (default `18`).
- **Logic**: If `login_hour < business_hours_start` or `login_hour >= business_hours_end`, `after_hours_activity = 1`, otherwise `0`.

### B. Rolling Temporal Window Derivations (Leakage Prevention)
To prevent temporal data leakage, all rolling window metrics are computed strictly backward in time $[t - \text{window}, t]$ after sorting events by `timestamp` chronologically:
1. **`events_per_user_1h`**: Count of all security events generated by the same `username` in the 1-hour window ending at event time $t$.
2. **`login_frequency_1h`**: Count of authentication events (`Failed Login`, `Login Success`, `Brute Force`) generated by the same `username` in the 1-hour window ending at event time $t$.
3. **`unique_destinations_24h`**: Count of distinct `destination_ip` addresses accessed by the same `username` in the 24-hour window ending at event time $t$.

---

## 5. Missing-Value Handling Strategy
- **Numeric Fields** (`failed_login_attempts`, `raw_cvss_score`): Coerced to numeric; missing values imputed with `0` or median.
- **Categorical Fields** (`protocol`, `event_type`, `event_status`): Handled gracefully by `OneHotEncoder(handle_unknown='ignore')`; missing values imputed with `'Unknown'`.
- **Severity Mapping**: Unrecognized or missing `event_severity` strings default safely to `1` (`Low`).
- **Post-Transformation Safety Check**: Any residual `NaN` or `inf` values post-transformation are imputed with `0.0`.

---

## 6. Encoding & Scaling Strategy
- **Categorical Encoding**: `sklearn.preprocessing.OneHotEncoder(sparse_output=False, handle_unknown='ignore')` transforms 3 categorical features into 19 binary columns.
- **Numerical Scaling**: `sklearn.preprocessing.StandardScaler()` normalizes 7 continuous numeric features (`failed_login_attempts`, `raw_cvss_score`, `severity_score`, `login_hour`, `events_per_user_1h`, `login_frequency_1h`, `unique_destinations_24h`) to zero mean and unit variance.
- **Binary Features**: Preserved unscaled as numeric `0.0` or `1.0` flags (`malware_detected`, `after_hours_activity`, `vulnerability_present`).
